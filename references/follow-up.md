# 行动复盘

只读取当前对话或用户带来的决策卡。没有旧卡时提示可补充原计划和新信息，也允许只用现有信息复盘；不要声称记得以前的对话。

## 先检查发生了什么

最多三个问题，按缺口选择：做了什么、观察到什么、新约束/诉求是否改变。用户选择少信息继续时直接做暂定复盘。

## 分开评价过程与结果

区分当时已知的信息、当时的判断依据、后来新增事实和随机结果。一次成功不证明方法正确，一次失败也不自动证明当时判断错误。行动完成、用户采纳、现实结果、决策过程质量分别记录在当前卡中，不互相替代。

## 没有推进时

| 可能原因 | 处理 |
|---|---|
| 动作太大或不具体 | 缩小成一次可完成、能减少未知的动作 |
| 缺资源、资格或信息 | 明确缺什么、如何获取，不能只要求勇气 |
| 重要目标冲突 | 重新核对优先级与可接受代价 |
| 方案不贴合诉求 | 修正问题卡和选项 |
| 主动决定暂缓 | 写理由、暂缓成本和重新评估条件 |

以上是候选解释，由用户核对；不默认惰性、恐惧或自我设限。

## 更新

指出具体新增信息如何改变原假设、目标或选项，然后更新条件式建议、下一步和复评条件。保留重要分歧，不为维护先前说法而忽视反证。

用户可带走更新后的决策卡；不默认落盘、建立个人档案或安排提醒。若发现可复现的系统问题，先给用户正确分析，再依 [进化机制](evolution.md)保存去除个人细节的错误模式。
