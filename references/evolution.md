# 分级进化与维护

## 何时启动

用户主动要求“进化人生导师”或修正问题；同类错误在三个独立案例中出现；或一次可复现的行为标准违规。主动要求可立即启动诊断或虚构测试，不要求先凑够三次；启动评估不等于发布更新。没有证据不更新，用户拒绝补充、未采纳、无反馈或单次结果好坏本身都不是失败。

先修正当前回答，再考虑通用方法。进化在活跃会话中进行，不建定时任务，不承诺后台自我改写。

## 状态位置与隐私

在本工作台，维护数据位于 `_agent/tools/life-director/`，源位于 `_agent/skills/life-director/`。安装到其他环境时明确指定一个可写、位于源目录之外的维护目录，不能默认写个人目录或改宿主配置。

初始化：`python3 scripts/maintain.py init-state --state-root <维护目录>`。所有路径参数由宿主传入，不复制本机绝对路径到其他用户环境。

`feedback.jsonl` 每行仅有：`issue_id`、`category`、`pattern`、`expected_behavior`、`version`、`synthetic_case_id`、`independent_occurrences`。用虚构场景表达错误，不记录原文、身份、金额、健康或家庭背景。不能安全去除个人细节的内容不落盘。计数依据独立案例，重复生成同一案例不增加次数。反馈撰写由主持人负责去除个人信息，脚本不会神奇地自动匿名化。

`candidates/` 放候选源；`evaluations/` 放虚构对话、评分、来源核验与审阅证据；`versions/` 放完整运行文件快照。维护数据不进入安装包或跨项目 Memory。

## 分级

| 等级 | 内容 | 应用 |
|---|---|---|
| patch | 表述歧义、重复指令、链接格式、已有范围的澄清 | 证据及测试通过后可自动更新，并说明变更 |
| method | 导师方法/职责、追问/补充提示、建议、复盘、来源纠错、维护代码改变 | 展示具体差异、依据与测试，直接获得用户确认后更新 |
| expansion | 新导师、领域、个人档案、外部能力、后台能力或不兼容改变 | 单独规划并确认后构建 |

扩大触发范围不是 patch。patch 的文件门槛由工具限制，但文件路径不能证明语义级别；执行者必须按实际影响分类，不能通过把大改写入 SKILL.md 规避确认。导师原文和来源只读到核验出错为止；来源修正属 method，不能为了支持建议修改出处。

## 操作闭环

1. 将通用错误转成虚构案例，写出预期行为和当前可复现失败。最多两轮修正，超过则停止。
2. 复制运行文件到新的候选目录，不直接改当前版。`snapshot` 保留旧版；候选编号与反馈对应。
3. 做最小修正，更新候选版本与 CHANGELOG：patch 更新末位，method 更新中位，expansion 更新首位。保留原测试案例和标准，新增目标案例，不改旧标准让候选“通过”。
4. 在当前版和候选版各运行同一虚构对话：每个用户回合等待真实执行回复后再给下一回合。保存实际输出。独立评估者按 rubric 判定，不把关键词检查或脚本结构检查当行为验证。
5. 按以下报告格式写评估；新目标案例也在旧版执行。检查全部 candidate 通过、旧通过项不退步，至少一项目标从失败到通过；旧版无法复现时继续观察，不更新。
6. `gate` 只校验报告完整性、证据存在、内容指纹和版本/文件级门槛，不判断报告内容是否诚实。主持人必须审读实际输出，保留评估者与执行者信息；没有评估工具时不能编写虚假的通过报告。
7. method/expansion 将具体候选差异与结果给用户确认，获得确认后记录其授权依据。patch 不需要额外确认。
8. `release` 再次核验门槛，先保存当前快照，再应用候选、打包并写版本操作日志。不删除文件；文件集发生不兼容变化时停止覆盖，另行规划。
9. 失败保留旧版和候选证据，不强行发布。报告明确哪些验证未执行；只读或无工具环境只交付修正方案。

维护工具在应用前及逐文件写入前重新检查源内容，发现未评估编辑则停止；这是一种乐观冲突检查，外部编辑器不遵守维护锁时仍需避免同时编辑。操作日志不可写时提前失败，后续记录失败会回退本次写入和安装包；回退发现并发修改时保留该修改并报告人工核对。安装包输出不得位于维护目录，也不得与自动备份路径相同。状态锁使用 POSIX fcntl，维护写操作需 Python 3.10+ 的 macOS/Linux 环境；其他宿主无法执行时只交付候选方案。

### 对比报告接口

JSON 字段：`baseline_sha256`、`candidate_sha256`（用 `check` 获取）、`attempt`（1 或 2）、`level`（patch/method/expansion）、`reviewer`、`target_cases`（案例 ID 列表）、`results`。

`results` 每项含 `id`、`baseline` 与 `candidate`（pass/fail）、`baseline_evidence` 与 `candidate_evidence`（相对维护目录的文件路径）、`reason`。证据必须位于 `evaluations/`，是该案例实际生成的虚构对话，报告覆盖当前版与候选版案例并集。未执行不是 pass，报告不完整会拒绝更新。

用户确认文件含 `candidate_sha256`、`level`、`confirmation`（对本次通用改动的明确确认依据，不含私人对话背景）。维护工具只校验文件字段，不代替宿主验证授权来自真实用户。

### 工具调用

在源目录执行，先使用 `python3 scripts/maintain.py --help` 查看参数。

- `check`：结构、引用、版本、案例与运行文件指纹；不是行为测试。
- `snapshot --state-root <目录>`：按版本和指纹保存快照，不覆盖旧快照。
- `package --output <人生导师.skill>`：构建 ZIP 格式安装包，包含 life-director 顶层目录；本工作台将旧包保留在维护目录的 versions，新环境可加 `--state-root <目录>`。未指定维护目录的独立打包将旧包留在输出目录，不覆盖未识别的文件。
- `inspect --archive <安装包>`：核对精确运行文件集与当前源的字节哈希。
- `gate --candidate <候选目录> --report <报告> --state-root <目录>`：只读检查候选是否可应用。
- `release`：使用同 gate 参数；method/expansion 另加 `--approval-file <确认文件>`；输出参数 `--output <安装包>`。
- `restore --snapshot <快照ZIP> --state-root <目录> --output <安装包>`：校验快照、保存恢复前版本、复制恢复并重新打包。不删除历史或其他内容。

升级安装包不等于宿主已安装。无重新安装的外部宿主仍用旧版；源目录在本工作台为唯一事实源。
